# Saga bootstrap and trust model

Saga publishes the source of its bootstrap implementation, target binaries,
and release hashes so that the bootstrap boundary is explicit rather than
hidden.

## Stages

- **Seed / Stage 0**: audited bootstrap source under `implementations/go/`.
- **Saga Native**: statically linked executable produced from the seed.
- **Saga application**: Saga Native + a canonical, SHA-256-authenticated Saga
  payload generated by `saga build`.

Applications produced at Stage 2 contain no Python bytecode, Python virtual
environment, Go toolchain, JVM, Node runtime, or C compiler dependency.

## Reproducibility checks

Release validation records:

- SHA-256 of every target Saga Native binary;
- `file`/PE/ELF architecture inspection;
- Linux static-link check;
- self-conformance results;
- execution with `PATH` pointing to an empty directory;
- standalone application generation and execution with the same empty PATH.

A future fully source-self-hosting compiler can replace Stage 0 without changing
Saga source semantics or the standalone bundle format.
