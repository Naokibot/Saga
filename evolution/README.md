# Saga Evolution Process

Language changes are proposed as **Saga Evolution Proposals (SEP)**. A proposal must contain Motivation, User model, Syntax, Static semantics, Dynamic semantics, Diagnostics, Teaching impact, Security impact, Compatibility/edition impact, Alternatives, Reference implementation and Conformance tests.

States: Draft -> Review -> Accepted/Rejected -> Implemented -> Stabilized. Accepted syntax does not enter a stable edition until implementation diversity and conformance evidence are recorded. Breaking changes require an edition boundary and a migration story.

No project maintainer may label an internal review as independent standards approval.
